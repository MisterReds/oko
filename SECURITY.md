# Безопасность ОКО

## Модель доверия в 0.4.2

Сервер преподавателя открывает два разных прослушивающих адреса:

- **127.0.0.1:7600** — HTTP/WebSocket для собственного нативного интерфейса. Соединение не покидает компьютер преподавателя.
- **0.0.0.0:7601** — TLS/WSS для подключений из локальной сети; включается преподавателем в окне ОКО. На этом порту доступны только `/ws/agent` и `/healthz`. **Маршруты** `/`, `/api/*`, `/ws/console` **отсутствуют даже при наличии административного токена**. Для тестов можно задавать отдельный адрес через `--tls-bind`.

У преподавателя и ученика **разные 256-битные случайные токены**. Ученический токен даёт право подключить агент; он не разрешает получать списки экранов или отправлять административные команды. Токены и приватный ключ не должны публиковаться в исходном коде, чатах или общедоступных логах.

TLS использует локально созданный самоподписанный сертификат. Для защиты от подмены сервера ученик обязан ввести **точный SHA-256 отпечаток сертификата**, полученный непосредственно от преподавателя. Клиент не принимает неподписанный сертификат, сертификат с другим отпечатком или незашифрованный ws:// вне localhost без явного CLI-исключения --allow-insecure.

При смене или повреждении TLS-ключей сначала остановите сервер; новые сертификаты и отпечатки нужно согласованно заменить на всех ученических компьютерах. Для восстановления доступа не удаляйте единственную копию идентификатора, пока школа не переподключила агентов.

## Совместимость аутентификации

Начиная с 0.4.2, агентский endpoint принимает `Authorization: Bearer <ключ ученика>`. Ранее использовавшийся параметр URL `?token=...` остаётся временно для совместимости с клиентами 0.4.x. При новом подключении следует предпочитать заголовок: адреса URL могут попадать в журналы сетевой инфраструктуры.

## Текущие ограничения

- Система ещё не прошла внешний аудит безопасности.
- Нет политики централизованного жизненного цикла сертификатов, обновления/отзыва отдельных ученических токенов и полноценного журнала действий администратора.
- Доступ из произвольной публичной сети не рекомендуется. Используйте защищённую локальную сеть и межсетевой экран.
- Захват экрана должен использоваться только с согласия и в соответствии с правилами образовательной организации.
- Блокировка X11 ограничена 120 секундами и снимается при завершении агента; это сделано для восстановления пользовательского управления.
- Wayland GNOME/KDE не поддерживается в части захвата через XDG ScreenCast Portal; ОС должна сама выдавать разрешения.

Сообщения об уязвимостях следует направлять владельцу репозитория через приватный канал GitHub Security Advisories, а не публиковать рабочие ключи в открытых Issues.

## Проверки

- Rust unit-тесты.
- Проверка ролей в API и WebSocket.
- Интеграция TLS, SHA-256 pinning и отказ при неверном сертификате.
- Повторное подключение после перезапуска сервера.
- X11 input grabbing и освобождение ввода после остановки агента.
- GUI smoke-тесты под Xvfb.
