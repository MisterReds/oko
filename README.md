# ОКО — нативное приложение для учебного класса

ОКО — открытое приложение на Rust для просмотра экранов ученических компьютеров и управления классом. **Преподаватель работает в собственном окне ОКО, без браузера**. Ученик запускает отдельное приложение настройки агента.

Текущая версия **0.4.2**. Это предварительный релиз: полноценная эксплуатация проверена на Linux/X11 в виртуальных средах, на физическом Calculate Linux отдельные испытания ещё необходимы.

## Установить за несколько минут

### Способ 1 — скачать готовые файлы

[**Скачать последний релиз ОКО**](https://github.com/MisterReds/oko/releases/latest)

| Файл | Назначение |
|---|---|
| OkoTeacher-0.4.2-x86_64.AppImage | Нативное приложение преподавателя |
| OkoStudent-0.4.2-x86_64.AppImage | Нативное приложение ученика |
| OkoNative-0.4.2-linux-x86_64.tar.gz | Универсальный portable-пакет |
| oko-native_0.4.2_amd64.deb | Debian/Ubuntu |
| OkoNative-0.4.2-FULL.zip | Полный комплект |

Для запуска AppImage достаточно дать файлу право на выполнение:

~~~bash
chmod +x OkoTeacher-0.4.2-x86_64.AppImage
./OkoTeacher-0.4.2-x86_64.AppImage
~~~

Для ученического ПК аналогично используйте OkoStudent.

**Calculate Linux, Gentoo, Fedora, Arch:** если в системе нет FUSE2, используйте режим:

~~~bash
./OkoTeacher-0.4.2-x86_64.AppImage --appimage-extract-and-run
~~~

Для готового графического приложения требуются Linux **x86-64**, glibc 2.35+ и графические библиотеки OpenGL/Mesa. Пакет AppImage включает дополнительные XKB-библиотеки, но не заменяет графический драйвер и сеанс рабочего стола.

### Способ 2 — установить прямо из GitHub

~~~bash
git clone https://github.com/MisterReds/oko.git
cd oko
bash scripts/install.sh both
~~~

Скрипт скачивает обе AppImage из последнего опубликованного GitHub Release, проверяет SHA-256 и создаёт ярлыки в меню приложений текущего пользователя **без sudo, Docker и Rust**. Можно установить одну роль: teacher либо student.

Установка и обновление выполняются одной командой. Новая версия сначала скачивается и проверяется по SHA-256, затем включается через атомарную символьную ссылку. Предыдущие бинарники сохраняются для отката. Конфигурация, TLS-ключи и согласованный автозапуск остаются.

~~~bash
# Установить или обновить обе роли до последнего релиза
bash scripts/install.sh both

# Посмотреть установленные версии
bash scripts/install.sh status

# Откат к предыдущему выпуску
bash scripts/rollback.sh both

# Удалить приложения, оставив настройки
bash scripts/uninstall.sh both

# Удалить приложения, настройки и TLS-ключи
bash scripts/uninstall.sh both --purge
~~~

Можно обновить только teacher или student. При обновлении старой 0.3.0 версии установщик перенастраивает существующий XDG-автозапуск ученика на стабильный путь. Установка не перезапускает приложение во время урока: для перехода на новую версию его необходимо перезапустить.


## Что нового в 0.4.2 — усиление безопасности и исправление исходного архива

- Публичный WSS-порт для ученических компьютеров теперь содержит **только** `/ws/agent` и `/healthz`. Административный API, веб-консоль и WebSocket преподавателя доступны исключительно на локальном интерфейсе `127.0.0.1`. Эти ограничения проверяются интеграционными тестами даже с корректным административным ключом.
- WSS-сервер принимает ключ ученика также через заголовок `Authorization: Bearer`. Для совместимости со старыми агентами 0.4.x **временно сохранён** прежний URL-параметр `token`; его удаление потребует согласованного обновления клиентов.
- Исправлен архив `OkoNativeSource`: структура соответствует Git-репозиторию, присутствуют скрипты сборки, документация и тесты. Автоматическая проверка теперь запускает `cargo metadata` из распакованного архива.
- Добавлена диагностика Linux: `bash scripts/doctor.sh` (архитектура, glibc, графический сеанс, FUSE). Она не подтверждает поддержку Calculate Linux без теста на самой ОС.

**Перед выпуском стабильной 1.0:** [проверяемые критерии и оставшиеся задачи](docs/RELEASE-1.0-CHECKLIST.md).

## Что нового в 0.4.1

Теперь окно ученика **не путает запуск процесса с подключением**. Отдельно отображаются установление связи, ожидание первого изображения, реальная передача кадров, переподключение и ошибки захвата. В интерфейсе показываются способ захвата, разрешение, возраст последнего отправленного кадра и последняя ошибка. Агент хранит техническое состояние в `~/.local/state/oko/agent-health.json` (либо в `$XDG_STATE_HOME/oko/agent-health.json`) с правами 0600; токены в этот файл не записываются. После прекращения работы процесса старый статус не отображается как действующий.

Обновлён CI: проверяется отключение сервера, возобновление потока и отказ в доступе к Wayland-захвату без подмены реального экрана демо-изображением.

## Подключить учебный класс

1. **На компьютере преподавателя** откройте ОКО Преподаватель. При первом запуске программа создаст отдельные административный и ученический ключи.
2. В боковой панели включите **«Разрешить подключения из LAN»**. Приложение запускает защищённый сервер **WSS на порту 7601**, а интерфейс преподавателя продолжает работать локально на 127.0.0.1:7600.
3. Преподаватель передаёт ученику **три значения**: WSS-адрес (например, wss://192.168.1.10:7601), **ключ ученика** и **SHA-256 отпечаток TLS-сертификата** из своего окна ОКО.
4. **На компьютере ученика** откройте ОКО Ученик и заполните эти поля, затем нажмите «Подключиться». Можно указать имя ПК и включить автозапуск с согласия пользователя.
5. Преподаватель увидит компьютер в сетке: миниатюра экрана, имя, статус и FPS. Возможны выбор нескольких ПК, просмотр на весь экран, блокировка и отправка уведомлений.

**Важно:** административный ключ никогда не передавайте ученикам. Отпечаток сертификата следует сверить по надёжному каналу; при его несовпадении подключение будет отклонено.

### Что изменилось с версии 0.2.0

- Внешнее сетевое подключение по незащищённому ws:// **отключено по умолчанию**; для LAN используйте wss:// на 7601 с отпечатком. Старые сохранённые адреса ученикам нужно обновить.
- Блокировка на X11 теперь перехватывает клавиатуру и мышь, а не просто показывает чёрный экран.
- Захват освобождает устройства при завершении агента; блокировка автоматически истекает через **120 секунд** для безопасности.
- Подтверждение блокировки приходит после фактического выполнения.
- Исправлено переподключение: при обрывах сети не должны накапливаться потоки захвата.
- Сервер выдаёт собственный сертификат для учебного класса и сохраняет закрытый ключ в пользовательском каталоге с ограниченными правами.

## Совместимость и ограничения

| Система / режим | Проверенный статус |
|---|---|
| Linux x86-64, X11 | Нативное окно, захват, ввод/блокировка проверены через Xvfb |
| Debian 12 / Ubuntu | Сборка, пакетная установка, GUI и TLS проверялись в изолированных окружениях |
| Calculate Linux, Gentoo + X11 | Portable/AppImage предусмотрены; физический Calculate Linux ещё не проверен |
| Wayland + wlroots + grim | Экспериментальный захват |
| GNOME/KDE Wayland | ScreenCast Portal пока не реализован |
| ARM64, Windows, macOS | Готовые пакеты не выпускаются |

Защищённое соединение TLS снижает риск перехвата экранов и команд, но **не заменяет сетевой аудит, мониторинг доступа и соблюдение правил образовательной организации**. Не публикуйте служебные порты в открытый интернет. Агенты работают в пользовательском сеансе; функции запуска до входа в систему и удалённой блокировки системного экрана входа не реализованы.

## Сборка из исходников

Требуются Rust 1.91.1+, Cargo, pkg-config, компилятор C, dev-пакеты X11/Wayland/OpenGL и системный шрифт DejaVu Sans. Для сборки самого приложения нужен доступ к зависимостям crates.io.

~~~bash
git clone https://github.com/MisterReds/oko.git
cd oko
bash scripts/build-local.sh
~~~

Результаты:

- target/release/oko-master — сервер;
- target/release/oko-agent — агент;
- desktop/target/release/oko-desktop — нативное окно.

Пользовательские данные (токены, ключи TLS и настройки) сохраняются в **~/.config/oko**, не включаются в исходный код или релиз.

## CI/CD

[GitHub Actions: Linux CI and Release](.github/workflows/linux.yml) автоматически:

- Проверяет Rust-тесты и разграничение административных/ученических прав.
- Проверяет TLS, отклонение чужого сертификата и восстановление связи.
- Проверяет реальную блокировку клавиатуры/мыши в X11 и снятие блокировки после отключения агента.
- Запускает оба нативных окна через Xvfb и тестирует защищённое сопряжение.
- Собирает AppImage, DEB и portable-архивы, проверяет SHA-256.
- При создании тега версии публикует **GitHub Release только после успешного CI**.
